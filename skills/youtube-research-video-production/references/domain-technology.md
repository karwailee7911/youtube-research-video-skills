# Technology and science evidence rules

Use this file only for technology, software, engineering, AI, or science topics.

## Source order

Prefer:

1. Official documentation, specifications, standards, and release notes
2. Source code, reproducible tests, and benchmark definitions
3. Primary papers and named datasets
4. Independent evaluations with disclosed hardware and methods

Record product or library version, release date, platform, hardware, configuration, dataset, metric, and test conditions. Browse current sources because versions and capabilities change.

## Required distinctions

- Announced feature versus shipped feature
- Demo versus reproducible capability
- Model score versus user outcome
- Latency versus throughput
- Client-side versus server-side behavior
- Open weights versus open source
- Security claim versus verified threat model

Run a reproducible test when a central claim can be checked locally. Do not generalize one benchmark, device, or prompt to all use cases. State the version and date near every time-sensitive conclusion.
